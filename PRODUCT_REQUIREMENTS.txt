灵鉴 · 多模态伪科普识别 — 需求说明（Requirements）
================================================================

本文档描述「识别能力 + 标准输出 + 用户端展示」的产品与技术需求，供研发、测试与验收对齐。实现以当前仓库代码为准，随迭代可修订。


1. 目标与范围
--------------

1.1 目标

对用户提交的文本 / 图片 / 图文混合内容进行自动研判，输出统一结构化的研判结果，并在用户端可读、可核对、可追溯。

1.2 范围

在内：同步识别接口、标准研判 JSON、推理缓存策略、结果页与分享摘要所需字段、原文高风险用语高亮规则。

不在此文档：具体模型选型、训练数据配比、标注规范细则（可由独立 ML 文档定义）。

1.3 非目标（澄清）

· 判定依据表述不当（如错误拼接 BERT 机读句与原文）首选通过服务端后处理与提示词约束解决，不要求为此单独「重训 BERT 分类器」。

· 原文高亮当前采用规则库 + 特征标签扩展词；若未来后端提供字符级 span，可升级为位置驱动高亮。


2. 统一输出（后端）
--------------------

2.1 响应结构

识别接口（如 AnalyzeResponse）须包含嵌套对象 standard_judgment，且与下列字段语义一致；同时可保留 bert / llm / final 等中间结果供调试或兼容。

2.2 standard_judgment 必填字段

字段名                  类型              说明
----------------------------------------------------------------------
content_id              string            与本次内容/请求一致的唯一标识
risk_level              枚举              "高" | "中" | "低"，展示用三档风险
comprehensive_score     number            综合得分 0–100，允许一位小数
logical_fallacy         string            逻辑谬误或不严谨论证类型；无则建议为「无」
scientific_error        string            科学事实层面的问题或不确定性说明；无则建议为「无」
core_features           string[]          伪科普/高风险特征标签列表
judgment_basis          string            综合判定依据：完整书面语段落，解释为何给出该档与得分
infer_time              string            服务端完成推理时间，格式 YYYY-MM-DD HH:MM:SS

2.3 输出格式约束

· 面向调用方的 LLM 原始输出应规整为单一 JSON（键名固定），不得依赖纯文本拼接或 Markdown 围栏作为主协议。

· judgment_basis 不得以 BERT 机读模板（如「风险X；命中标签：…；总得分：…/100」）作为对外主体，也不得大段粘贴输入原文；若模型违反，服务端须改写为符合 2.2 的叙事段落。

· BERT 侧 prediction_summary_zh 不得包含「阈值」等调试片段（避免进入展示链路）。

· content_id 与 infer_time 由服务端注入并校验，避免模型编造。

2.4 推理缓存（Redis）

· 可对「同用户 + 同输入摘要」的识别结果做短期缓存以降本。

· 变更输出协议、提示词、后处理逻辑时，须通过 LINGJIAN_INFER_CACHE_VERSION 或内置缓存版本串使旧缓存失效，避免用户长期看到过期结构或过期文案。

· 部署或排障时：重启进程、提升缓存版本或清理 infer:* 键为常规手段。


3. 用户端（前端）
------------------

3.1 结果页 — 判定依据（结构化展示）

「判定依据」不得仅展示一段合并长文作为唯一形态，须分维度呈现（数据来源于 standard_judgment / llm 对齐字段）：

  1）逻辑谬误 — logical_fallacy
  2）科学事实错误 — scientific_error
  3）核心特征 — core_features（标签化展示）
  4）综合判定依据 — judgment_basis（完整总结段落）

某一维无内容时须有明确空态（如「—」或「暂无显性命中特征」），避免与序号组件混淆造成误读。

3.2 结果页 — 原始识别内容（高风险用语高亮）

· 「原始识别内容」模块须对正文中的绝对化用语、疗效夸大、传言式表述等高风险片段进行红色高亮（样式显著、可读性优于纯黑字）。

· 实现可采用：内置话术正则 + 结合 core_features / BERT 命中标签扩展关键词扫描；命中区间合并，避免重复嵌套标签破坏排版。

· 优先避免整段不可信 HTML 注入；推荐使用分段渲染（text + mark）而非未过滤的 v-html。

3.3 分享 / 历史列表

· 分享摘要可将结构化要点压缩为多行列表；历史列表得分与风险档位须与 standard_judgment 一致，得分支持小数展示规则。


4. 运维与验收
--------------

4.1 部署后检查

· 后端进程重启后新代码生效；变更环境变量（如是否启用 LLM）须重启。

· 前端静态资源更新后用户需刷新或重新构建部署。

4.2 验收建议用例

1）低风险科普句：standard_judgment 字段齐全，judgment_basis 为书面总结，非机读摘要句。

2）高风险营销句：结构化四维有内容；原文中典型话术被标红。

3）同文重复请求：在缓存 TTL 内结果一致；提升缓存版本后旧键不再命中。

4）历史记录：列表得分与详情页 comprehensive_score 一致（小数规则一致）。
